4.3 Implementasi Basis Data

Implementasi basis data merupakan tahap penerjemahan rancangan konseptual (Entity Relationship Diagram) ke dalam bentuk fisik basis data pada Relational Database Management System (RDBMS). Sistem Informasi Pelayanan Keluarga Berencana (KB) ini diimplementasikan menggunakan DBMS MySQL/MariaDB dengan storage engine InnoDB untuk mendukung integritas referensial data (Foreign Key Constraints) serta character set utf8mb4.

Tabel-tabel basis data yang terbentuk pada sistem ini terdiri dari 10 (sepuluh) tabel utama yang saling berelasi, yaitu: tabel instansis, wilayahs, users, alokons, peserta_kbs, skrining_medis, informed_consents, pelayanans, jadwal_pelayanans, dan antrian_jadwals. Detail struktur kamus data dari masing-masing tabel dijelaskan pada uraian berikut.

4.3.1 Tabel Struktur Tabel Instansi

Tabel instansis digunakan untuk menyimpan data fasilitas kesehatan atau klinik yang menyelenggarakan pelayanan KB.

Tabel 4.1 Struktur Tabel Instansi (instansis)
No Nama Kolom (Field) Tipe Data Panjang Null Kunci Keterangan
1 id BIGINT 20 NO PK ID unik instansi (Auto Increment)
2 nama_instansi VARCHAR 255 NO - Nama faskes / instansi pelayanan
3 kode_faskes VARCHAR 50 NO Unique Kode unik identitas fasilitas kesehatan
4 created_at TIMESTAMP - YES - Waktu data dibuat
5 updated_at TIMESTAMP - YES - Waktu data terakhir diperbarui

4.3.10 Tabel Struktur Tabel Antrian Jadwal

Tabel antrian_jadwals digunakan untuk mengelola nomor urut registrasi akseptor serta status kehadiran.

Tabel 4.10 Struktur Tabel Antrian Jadwal (antrian_jadwals)
No Nama Kolom (Field) Tipe Data Panjang Null Kunci Keterangan
1 id BIGINT 20 NO PK ID unik antrean (Auto Increment)
2 jadwal_pelayanan_id BIGINT 20 NO FK Relasi ke jadwal_pelayanans.id
3 peserta_kb_id BIGINT 20 NO FK Relasi ke peserta_kbs.id
4 nomor_antrian INT UNSIGNED 10 NO - Nomor urut antrean akseptor
5 status ENUM - NO - Status kehadiran (terdaftar, hadir, tidak_hadir)
6 created_at TIMESTAMP - YES - Waktu data registrasi dibuat
7 updated_at TIMESTAMP - YES - Waktu status antrean diperbarui
Catatan Relasi & Batasan (Unique Constraint):
Pada tabel antrian_jadwals, diterapkan composite unique key pada kombinasi (jadwal_pelayanan_id, peserta_kb_id) untuk menjamin integritas data bahwa satu orang akseptor hanya dapat terdaftar pada satu nomor antrean dalam sesi jadwal pelayanan yang sama.
